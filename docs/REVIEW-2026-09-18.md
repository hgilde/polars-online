## 2. Findings (candidates until §0 phase 2 says otherwise)

### B1. A backwards clock on a session change bypasses `on_clock_reset` — *lost guard*

**Where.** `crates/online-core/src/clock.rs:207-247`, `ClockState::advance`.
**Claim.** When `session_changed` and `cfg.session_gap` is `None`, the delta is
`raw.clamp(0.0, max_dclock)`: a negative raw delta becomes 0 silently. The `raw < 0.0`
arm that consults `on_clock_reset` (`Max` / `Zero` / `ResetState` / `Error`) is reached
only when the session did *not* change. So `on_clock_reset = "error"` — whose stated
purpose (line 59) is to make a mis-sorted chunk loud — never fires on a row whose
session id also changed, and `reset_state` never resets there.
**Evidence.** `if session_changed { match cfg.session_gap { …, None => { capped = raw >
cfg.max_dclock; raw.clamp(0.0, cfg.max_dclock) } } } else if raw < 0.0 { match
cfg.on_clock_reset { … } }`. The test `session_gap_overrides_delta` covers `Gap(7.5)`
("session gap wins") and `Reset`, never `None`.
**Consequence.** Interleaved or mis-sorted rows that happen to change session are
absorbed as a zero delta under every policy, including the one chosen to refuse them.
**Fix / test.** With `session_gap: None` a session change is an ordinary row for the
clock: fall through to the `raw < 0.0` policy. Test: `Error` policy, sessions 1 → 2 with
clock 10 → 4, expect `backwards == Some(-6.0)`; `ResetState` expects `reset`. Read PLAN
§3 for what is promised before changing.
**Status.** candidate.

### S1. The sign hit rate does not age on an excluded `y = 0` row — *inconsistent, low*

**Where.** `crates/online-core/src/stats.rs:283-313`, `SlotMetrics::update`.
**Claim.** A row skipped for a non-finite `pred`/`y` or `w <= 0` ages every estimate
(`joint.decay(lam)`, `hit_w *= lam`, lines 288-289). A finite row with `y == 0` under
`binary = false` is scored into `ic`/`r2` (`joint.update`, `mse`) but the hit-rate
branch (`if binary || y != 0.0`) is skipped whole, so `hits`/`hit_w` are neither scored
nor decayed. The hit rate then runs on a different clock from `ic` and `r2` whenever the
target is exactly zero (discrete or rounded targets).
**Fix / test.** `else { self.hit_w *= lam; }` on the excluded path. Test: 100 rows of
`(0.9, 1.0)` then 100 of `(0.9, 0.0)` at `lam = 0.9`: `hit_w` must shrink by `0.9^100`.
**Status.** candidate (low). Changes `hit_rate` only on streams with exact zeros — the
user's call.

### B2. `coef_prior` is ignored by the standardized solve through the origin — *silent wrong output*

**Where.** `crates/online-core/src/ewridge.rs:742-752` (the call) and `804-844`
(`solve_scaled_through_origin`).
**Claim.** `solve` has four branches. `ridge_decay` adds `ps·ridge·c0` to the right-hand
side (line 717-723); plain through the origin adds `ridge·c0` (734-740); the centred
solve, plain or standardized, adds `ridge·c0·s` on the scaled system (912-914). The
fourth — `add_intercept = false` with `standardize = true` — passes the bare `b` to
`solve_scaled_through_origin`, which scales, solves and unscales it and never reads
`self.cfg.coef_prior`. The prior is silently dropped: the fit shrinks toward zero.
**Evidence.** `Self::solve_scaled_through_origin(cov, &mut failures, &zidx, &b, kc, mr,
ridge)` — no `coef_prior` argument; the function body has no `c0`. `validate` (189-309)
checks the prior's shape and finiteness only; nothing refuses this combination. The
only prior-with-standardize test, `coef0_works_with_standardization` (1215), keeps the
intercept.
**Consequence.** A user asking for a warm-started, standardized, no-intercept fit gets
an un-warmed one with no error, and under an overwhelming ridge the coefficients are 0
where the docs promise `coef_prior`.
**Fix / test.** Pass `coef_prior` and `readers` in; add `ridge * c0[j][zidx[i]] * s[i]` to
`bsub[j*kk+i2]`, the same form as line 913. Test: `add_intercept = false, standardize =
true, ridge = 1e12, coef_prior = [[3, -2]]` → coefficients within `1e-3` of the prior;
fails today (lands at ~0). A second case at a small ridge against the plain
through-origin path with the same prior, which must agree to `1e-6` on well-scaled data.
**Status.** candidate.

### P1. A windowed `ew_ridge` builds its O(k²) snapshot on every row, even when the cadence discards it — *performance, low*

**Where.** `crates/online-core/src/ewridge.rs:986-996`, `step`.
**Claim.** `let snap = RidgeMoments { acc: self.acc.snapshot(lam), … }` runs before
`win.snaps.offer(t, || snap)`; the closure only moves an already-built value.
`Acc::snapshot` copies every Gram's `k×k` co-moments (`Moments::of` → `to_vec`) and the

**Fix / test.** Build inside the closure: `offer(t, || RidgeMoments { acc:
self.acc.snapshot(lam), … })` — the borrow needs `acc`, `wsig`, `sig2` split from `win`
(they already are distinct fields). Bench at `k = 1000, window_every = 16`. Check the
other windowed models (`ewcov`, `lasso`, `marginal`) for the same pattern when read.
**Status.** candidate (low).

### S2. `robust` keeps raw cross-moments, so a level costs the fit `L²·ε` — *silent wrong output* (the N1/N2 defect, unfixed here)

**Where.** `crates/online-core/src/robust.rs:496-498` (the accumulator), `308-314` and
`329-332` (the plain solve), `409-412` (the standardized solve).
**Claim.** `r_j` is the EW mean of `z·target` — raw, with the intercept slot carrying
`ȳ` and each feature slot `E[x_i·y]`. The plain solve then reads the raw normal
equations `E[z zᵀ]β = r` (`a[i*k+jj] = self.cov[j].raw(i, jj)`), whose condition number
at a level `L` is `~L²/Var`; the standardized solve centres by subtraction,
`bsub = (b[i+off] − mean(i+off)·ybar)/s[i]`, two numbers of size `L²` leaving one of
size `Cov`. `ew_ridge`'s module doc states the consequence for exactly this form: "the
raw normal equations, or a right-hand side formed as `E[z y] − m ȳ`, lose `level²·ε`,
which at `1e8` is the whole fit". The 2026-09-12 round moved `ew_ridge` (N1) and `lasso`
(N2) to centred cross-moments (`crate::gaps::Cross`); `robust` was not moved, and its
docs do not say so.
**Evidence.** `robust.rs:497`: `*ri = a * *ri + bb * zi * target;` — no centring, no
`Cross`. Both `ewridge.rs` and `lasso.rs` carry `a_level_costs_the_fit_nothing` /
`a_level_costs_the_path_nothing` at `1e8`; `robust.rs` has no such test.
**Consequence.** Huber or quantile regression of a price on prices (the README's use
case) at a level of `1e8` returns slopes that are rounding noise, with no error and no
counted failure; at `1e4`–`1e6` the loss is partial and invisible.
**Fix / test.** Test first, from `ewridge.rs:2655`: Huber with `delta = 1e9` (least
squares) on the same stream at level 0 and `1e8`, slopes must agree to `1e-6` and
predictions minus the level to `1e-5`; expect it to fail today by orders of magnitude.
Then keep `r_j` centred as `Cross` does (mean of `z` over the target's *robust* weight,
`ȳ`, `c_j = E[(z − m)(y − ȳ)]`), and solve the centred system with the intercept
eliminated as `EwRidge::solve_centred` does; the quantile nudge enters `c_j` as
`nudge·(z − m)/aged` with `ȳ` untouched (a nudge has no target). Schema bump: `r`'s
meaning changes (`SCHEMA_VERSION` 11, `MIN` 11 under the pre-1.0 waiver — the user's
call).
**Status.** candidate — needs the reproduction before anything else.

### B3. `Rls::restore` and `Robust::restore` accept a state of any shape — *crash instead of an error, low*

**Where.** `crates/online-core/src/rls.rs:284-297`, `robust.rs:565-578`; also
`lasso.rs:703-722` for `sel_err`/`sel_w`/`sel_idx`.
**Claim.** `EwRidge::restore` and `Lasso::restore` refuse a state whose accumulators do
not match `cfg` (`has_shape` → `StateError::Invalid`). `Rls::restore` only resizes the
scratch buffers; `Robust::restore` only `zbuf`. A state whose `r` is shorter than
`k_total²`, or whose `cov` has fewer entries than `n_targets`, restores and panics on the
first `step` (`self.r[row + i]`, `self.cov[j]`). `Lasso` checks `acc` but not
`sel_idx`, whose entries index `lasso_path` in `lam_selected`.
**Consequence.** A hand-edited JSON state (`Bank::save_json_string` exists for that)
or a truncated file crashes the process instead of returning the error the bank
reports for every other model.
**Fix / test.** A `has_shape` per model, checked in `restore`; test: a state with
`r` truncated by one element restores as `Err(StateError::Invalid)`. Keep a list of
every model found without the check as the read continues.
**Status.** candidate (low). Models without a shape check so far: `rls`, `robust`,
`pa` (`beta` vs `n_targets`), `ftrl` (`n`/`zz`; and `prox` is `#[serde(default)]`, so a
state without it loads with `prox = []` and `self.prox[j][i]` panics on the first
step); `lasso` (selection fields); `deco` (`rho`/`rho_bar` lengths, and `blocks` is
read from the state — an index `>= n_features` panics in `block_sums`); `ew_cov`
(`EwCovModel::restore` checks nothing: `cov.k()` vs `cfg.n_features`, `mahal_q.len()`

### B4. `SgdCfg::validate` lets a NaN `clip_gradient` through to `f64::clamp`, which panics — *crash, low*

**Where.** `crates/online-core/src/sgd.rs:159-161` (the check), `583`, `587`, `594`,
`599` (the clamps); `178-182` for `InvScaling { power }`.
**Claim.** `if self.clip_gradient <= 0.0` is false for NaN, so the config validates;
`(d * zi * weight + l2 * *b).clamp(-clip, clip)` then panics on the first learned row
("min is NaN"). The validator's own comment for Huber's `delta` (line 163) states the
hazard: "NaN too: `f64::clamp` panics on a NaN bound." `clip_gradient` is serialized
`with = "f64_or_tag"`, so a JSON spec can carry `"nan"`. `InvScaling { power: NaN }`
passes `power < 0.0` and gives `lr = NaN`, NaN coefficients for the life of the state.
**Fix / test.** `if !(self.clip_gradient > 0.0)` (NaN-safe) and `if !(power >= 0.0)`;
tests in `cfg_validation_rejects_each_bad_field`: `clip_gradient = NaN` and
`power = NaN` both refused. Whether the spec layer already blocks them is V7's
question; the crate should not rely on it.
**Status.** candidate (low).
